## ส่วน A · บั๊กที่ตรวจพบ (มีหลักฐานจริง)

### A1 · รูปวัสดุหายในหน้า catalogue ขั้นที่ 1 (ยืนยันแล้ว)
- `/catalogue` ขั้น "1 เลือกวัสดุหลัก" แสดง 4 การ์ด (white_plain / other_plain / speckled / veined) เป็น **ข้อความล้วน ไม่มีรูปเลย**
- ต้นเหตุในโค้ด: `support-catalogue-workbench.tsx` ฟังก์ชัน `options` — ตัว `materialOptions` **ไม่มีฟิลด์ `imageUrl`** ขณะที่ `colourMap` / `sinkOptions` มี
- หลักฐานจำนวน: การ์ดวัสดุ 4 ใบ img ที่มี src = 0 ใบ
- **แก้:** ใส่รูปตัวแทนวัสดุ — ใช้ `imageUrl`/`slabImageUrl` ของสีแรกใน tier แสดงเป็นตัวอย่างพื้นผิว + ใช้ `fallbackLabel` (2 ตัวอักษร) ต่อไปถ้าไม่มีรูป

### A2 · ตัวโหลดรูปแบบ lazy หา container ผิด (บั๊กแฝง ทำให้รูป "เหมือนหาย")
- `catalogue-image-viewer.tsx:34` หา scroll root ด้วย `node.closest('[data-testid^="list-catalogue-"]')`
- หน้า design ใช้ `list-catalogue-colours` / `list-catalogue-basins` → **ตรง**
- แต่ workbench ใหม่ใช้ `list-support-catalogue-<category>` → **ไม่ตรง** (ขึ้นต้นด้วย `list-support-`)
  → `closest()` คืน null → observer ผูกกับ viewport แทน container ที่เลื่อนอยู่
  → ถ้า workbench ถูกวางในแผงที่เลื่อนภายในตัวเอง รูปจะ **ไม่โหลดเลย** (ค้างที่ src ว่าง)
- **แก้:** ให้ตัวเลือก container ครอบทั้งสองแบบ เช่น
  `node.closest('[data-testid^="list-catalogue-"], [data-testid^="list-support-catalogue-"]')`
  plus fallback ปลอดภัย: ถ้าไม่พบ container ให้ตั้ง `shouldLoad = true` ทันที (ห้ามค้างเงียบ)

### A3 · ตัวเลขวัสดุไม่ตรงกันในหน้า catalogue
- การ์ดหมวด "สี" แสดง **128** แต่ tier วัสดุแจกแจง 4 / 3 / 35 สี → ตัวเลขรวมขัดกันเอง
- **แก้:** ใช้ตัวเลขจากแหล่งเดียว (สีที่ไม่ซ้ำใน `pricingCatalogue`) ให้ทั้งสองที่ตรงกัน และถ้าไม่รู้ให้ขึ้น "—" ห้ามเดา

### A4 · เปิดแผง "น้องไนท์" แล้วหน้าออกแบบถูกบีบ
- เปิดแผงด้านขวาบนหน้า `/design` → คอลัมน์ PLAN STUDIO ยุบจนตัวอักษรเรียงแนวตั้ง (อ่านไม่ได้)
- **แก้:** แผงต้องไม่บีบพื้นที่ทำงาน — ให้ overlay ทับ หรือบีบแบบจำกัดความกว้างขั้นต่ำ + ซ่อนคอลัมน์ข้างอย่างสง่างาม (responsive) ไม่ให้ตัวอักษรแตกเป็นแนวตั้ง

### สิ่งที่ **ไม่ใช่** บั๊ก (ตรวจแล้วปกติ — ห้ามแก้)
- เซิร์ฟเวอร์รูป: swatch 86 ไฟล์ · slab 84 · basin 31 · ยิงจริงได้ HTTP 200 `image/png` ทุกไฟล์

## ส่วน B · ข้อโต้แย้งของ Replit — เดวิดสรุปคำตัดสิน

### B1 · "ข้อมูลบริษัทไม่ควรเป็น Single Source of Truth ฝั่งเว็บ" → **เห็นด้วย**
- แก้สถาปัตยกรรมเป็น:
  1. ค่าคงที่ข้อมูลบริษัทวางไว้ **ฝั่ง server** (โมดูลค่าคงที่ตัวเดียวของ API) — ไม่กระจายในโค้ดเว็บ
  2. ตอนกด "ออกใบเสนอราคา" → **คัดสำเนาข้อมูลบริษัท + เงื่อนไขการชำระเงิน + บัญชีธนาคาร ลงใน snapshot** (freeze)
  3. ใบที่พิมพ์/เปิดย้อนหลัง อ่านจาก snapshot ที่ freeze แล้วเท่านั้น — บริษัทแก้ข้อมูลภายหลัง **ต้องไม่เปลี่ยนเอกสารเก่า**
- ไฟล์ `company-info.ts` ฝั่งเว็บให้เหลือบทบาท "ค่าเริ่มต้นสำหรับ draft ที่ยังไม่ออกใบ" เท่านั้น ห้ามเป็นแหล่งจริงของเอกสารที่ออกแล้ว
- ข้อมูลที่ต้อง freeze: ชื่อบริษัท · เลขประจำตัวผู้เสียภาษี · ที่อยู่ · โทร · อีเมล · บัญชีธนาคาร · เงื่อนไขชำระเงิน · กำหนดยืนราคา · เวลารับสินค้า · ข้อความเงื่อนไขท้ายใบ

### B2 · "เลขที่เอกสารต้องตรวจซ้ำและล็อกตอนออกใบ" → **เห็นด้วย**
- ทีมขายยังกรอกเองตามรูปแบบ `Sep 26 / US / 0754`
- server ต้อง: ตรวจรูปแบบ · **ตรวจเลขซ้ำ (unique)** · ล็อกเลขพร้อม snapshot เมื่อกดออกใบ
- แก้ภายหลัง = **สร้าง revision ใหม่** (ฉบับที่ 1, 2, ...) ไม่ทับเอกสารเดิม · ใบที่พิมพ์ต้องแสดงเลขฉบับด้วย
- ย้ำ: ห้ามระบบสร้างเลขเองถ้าทีมขายยังไม่กรอก

### B3 · "แก้ draft แล้วล้าง calculationSnapshotId" → **ปัญหาจริง แต่แก้ให้ถูกทาง**
- ตรวจยืนยันแล้ว: `artifacts/api-server/src/routes/quotes.ts` บรรทัด 229 ตั้ง `calculationSnapshotId: null` ทุกครั้งที่ PATCH draft และบรรทัด 250 บันทึก `invalidatedSnapshot` ใน audit log
- **ห้ามแก้แบบ "ไม่ล้าง"** — เพราะ draft ที่แก้แล้วไม่ตรงกับ snapshot เดิม ถ้าไม่ล้างจะแสดงราคาเก่าผิด
- **แก้ให้ถูก:** เก็บ snapshot ไว้เสมอ (ห้ามลบแถว) + ทำสาย revision:
  - draft แก้ได้ปกติ แต่ snapshot ที่ถูกแทนต้องมีสถานะ `superseded` + ตัวชี้ไป revision ถัดไป
  - ใบที่ออกแล้วผูกกับ snapshot ของตัวเองแบบถาวร
  - เปิดดูย้อนหลังได้ว่าใบที่ X คำนวณจากอะไร ใครแก้อะไร เมื่อไร

### B4 · สรุปสถาปัตยกรรมที่ต้องการ (auditable)
```
draft (แก้ได้เสมอ)
   └─ คำนวณฝั่ง server → calculation_snapshot (เก็บทุกครั้ง ห้ามลบ)
        └─ กด "ออกใบเสนอราคา" → freeze: ข้อมูลบริษัท + เลขที่เอกสาร (unique) + ตัวเลข + revision
             └─ พิมพ์/PDF  ← อ่านจาก frozen snapshot เท่านั้น
แก้ไขภายหลัง → revision ใหม่ (ไม่ทับใบเดิม)
```

## เกณฑ์ตรวจรับ
```
A1 การ์ดวัสดุทั้ง 4 มีรูปตัวอย่าง (หรือ 2 ตัวอักษรสำรองถ้าไม่มีรูป) — แนบภาพ
A2 มี testid ยืนยัน: รูปใน list-support-catalogue-* โหลดได้จริงเมื่ออยู่ในแผงที่เลื่อนเอง (แนบภาพ + ค่า naturalWidth > 0)
A3 ตัวเลขสีของหมวด "สี" ตรงกับผลรวม tier (หรือขึ้น "—") — แนบภาพ
A4 เปิดแผงน้องไนท์แล้วหน้าออกแบบอ่านได้ปกติ (ไม่แตกแนวตั้ง) ทั้ง desktop และ mobile — แนบภาพ 2 ขนาด
B1 ออกใบแล้ว → แก้ข้อมูลบริษัทฝั่ง server แล้วเปิดใบเก่า ต้องยังแสดงข้อมูลเดิม (แนบหลักฐาน)
B2 กรอกเลขซ้ำ → server ปฏิเสธ · แก้เลขหลังออกใบ → ได้ revision ใหม่ ไม่ทับเดิม (แนบหลักฐาน)
B3 แก้ draft แล้ว snapshot เดิมยังอยู่ใน DB สถานะ superseded + ตามสาย revision ได้ (แนบ query + ผล)
```
