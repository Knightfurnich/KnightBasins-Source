## เรื่องที่ 1 (สำคัญสุด) — `sink-geometry.ts` ต้องรับ `D` ด้วย ไม่ใช่แค่ `Ø`

**บริบท:** อ่างทรงกลม 4 รุ่น (KF023–KF026) เคยวาดเป็น **สี่เหลี่ยม 0.35 × 0.15 ม.** แทนวงกลม Ø0.35 ม.
เพราะฝั่งข้อมูลส่ง `"D350x150"` (ตัวอักษร D) แต่ parser ตรวจเฉพาะ `"Ø"` / `"ø"`
รอบนั้นฝั่งผมแก้ข้อมูลเป็น `"Ø350x150"` แล้ว ของจึงถูก — แต่ถ้าข้อมูลเพี้ยนแบบเดิมอีก จะพังเงียบ ๆ อีก

**หลักฐานการวัดจริง (ก่อนแก้ข้อมูล):**
```
document.querySelector('[data-testid="overlay-basin-KF023"]').getBoundingClientRect()
-> 32 x 14 px  (สเกล 92 px/ม.) = 0.35 x 0.15 ม. · border-radius 18%  = สี่เหลี่ยม (ผิด)
```

**ต้องทำ:** ให้ `parseBowlDimensions()` ใน `artifacts/knightdesign-web/src/lib/sink-geometry.ts`
ยอมรับ prefix ของวงกลมแบบ case-insensitive: `Ø`, `ø`, `D`, `d` (และ `⌀` ถ้ามี)
พร้อมอัปเดต `sink-geometry.regression.ts` ให้มีเคส `"D350x150"` และ `"d350x150"` ด้วย

**เกณฑ์ตรวจรับ**
```
1. KF023 -> ช่องเจาะเป็นวงกลม กว้าง = สูง = 32 px (0.35 ม.) · border-radius 9999px
2. เพิ่มเทสต์ "D350x150" -> ได้ { shape: "circle", widthMeters: 0.35, depthMeters: 0.35 }
3. KF003 (350x500x130) ต้องยังเป็นสี่เหลี่ยม 0.35 x 0.50 ม. เท่าเดิม (ห้าม regress)
4. KF029 (bowl_mm = null) ต้องยังไม่วาดขนาด + ขึ้นข้อความ "ขนาดหลุมอ่างไม่ระบุในแคตตาล็อก"
```

## เรื่องที่ 2 — ช่องค้นหาสี ต้องค้น "รหัส" แบบ substring ได้

**บริบท:** `design.tsx` ค้นชื่อแบบ substring แต่ค้นรหัสแบบ **ตรงตัว** (`normalizeCode(colour.code) === codeQuery`)
ผลคือทีมขายพิมพ์รหัสไม่เต็มก็ไม่เจอ และป้ายในช่องบอกว่า "ค้นหาสีจากรหัสหรือชื่อ" (ไม่ตรงกับพฤติกรรม)

**หลักฐานการวัดจริง (production, พิมพ์จริง):**
```
พิมพ์ "SG"        -> 0 รายการ (ขึ้น "ไม่พบสีจาก server")
พิมพ์ "420"       -> 0 รายการ
พิมพ์ "SG420"     -> 1 รายการ (SG 420)
พิมพ์ "Sanded"    -> 7 รายการ
```

**ต้องทำ**
1. ค้นรหัสแบบ substring (หลัง normalize: ตัดช่องว่าง + upper) เช่น `SG`, `420`, `SG420` ต้องเจอ `SG 420`
2. ตัวอักษรพิมพ์เล็ก/ใหญ่ และช่องว่างต้องไม่ทำให้พลาด (`sg 420`, `SG420` ต้องเจอเหมือนกัน)
3. รหัสสีคือตัวตนของสี: `KZ802` กับ `KZ802N` ต้องไม่ถูกยุบรวมกัน

**เกณฑ์ตรวจรับ** (ส่งผลการพิมพ์จริงทุกรหัสกลับมา)
```
"SG" -> >=1 · "420" -> >=1 · "SG420" -> 1 · "sg 420" -> 1 · "KZ802" -> 1 · "KZ802N" -> 1 (คนละรายการ)
```

## เรื่องที่ 3 — บันทึก draft แล้ว ต้องกลับเข้าหน้าออกแบบได้ตรง ๆ

**บริบท:** กด "บันทึก draft" แล้วแอปพาไป `/quote/<id>` (หน้ามุมมองใบเสนอราคา)
แต่หน้าออกแบบโหลด draft กลับได้เฉพาะเมื่อ URL มี `?quoteId=<id>` — ผู้ใช้ทั่วไปไม่รู้ จึงเหมือน "กลับเข้าไปแก้ไม่ได้"

**หลักฐานการวัดจริง:** `save -> /quote/453d7571-...` · เปิด `/design` เฉย ๆ ได้ draft อื่น (ไม่ใช่ตัวที่เพิ่งบันทึก)

**ต้องทำ:** มีทางกลับเข้าหน้าออกแบบจาก draft ที่บันทึกแล้วอย่างชัดเจน (ปุ่ม/ลิงก์ "แก้ไขต่อในหน้าออกแบบ"
ที่พาไป `/design?quoteId=<id>`) หรือจำ draft ล่าสุดแล้วโหลดให้เมื่อเข้า `/design`

**เกณฑ์ตรวจรับ:** บันทึก draft → กดปุ่ม/ลิงก์ → อยู่ในหน้าออกแบบที่โหลด draft นั้นจริง
(อ่างที่เลือก + ตำแหน่งช่องเจาะที่ลากไว้ต้องกลับมาครบ)
