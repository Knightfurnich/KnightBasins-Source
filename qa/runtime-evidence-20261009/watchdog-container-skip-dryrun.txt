# หลักฐานดิบ: กลไก "container ที่หยุดโดยเจตนา" (ตามที่ 294-Q ข้อ D.5/E ขอ)

**เก็บเมื่อ:** 9 ต.ค. 69 (TH) · **คำสั่ง:** รัน `bin/knight_watchdog.sh` สองรอบบน **สำเนาชั่วคราว** (`/tmp/wd/wd.sh`) ที่ชี้ไฟล์ state คนละไฟล์ — **ไม่แตะ production, ไม่แตะไฟล์จริง, ลบไฟล์ชั่วคราวแล้ว**

ไฟล์จริงที่ควบคุม: `/opt/data/state/intentionally-stopped-containers`
```
knight-images-admin
n8n-n8n-1
```

## (1) เอาชื่อ `knight-images-admin` ออก → watchdog ต้อง "เตือน"
```
📢 รายงานเฝ้าระวังระบบอัตโนมัติ (Watchdog)
----------------------------------------
⚠️ เรื่องที่ต้องแจ้งให้ทราบ:

- หน้าจัดการรูปภาพสินค้าใช้งานไม่ได้ — ทีมงานอัปโหลดรูปไม่ได้
```

## (2) ใส่ชื่อกลับ (ไฟล์จริง) → watchdog ต้อง "เงียบ"
```
output: (ว่าง = เงียบ)
```

⇒ **กลไกทำงานสองทางตามที่ออกแบบ:** container ที่บอสหยุดเองเพื่อทดสอบ (n8n · images-admin) จะไม่ถูกเตือนซ้ำ · แต่ถ้าเอาชื่อออก (หรือ container ที่ *ไม่ได้* ตั้งใจหยุดล่ม) จะกลับมาเตือนทันที

## บริบท: ทำไมต้องมีกลไกนี้
บอสหยุด container 2 ตัวเพื่อทดสอบ (9 ต.ค. 69): `n8n-n8n-1` (ไม่เคยมี execution เลย = 0 ครั้ง) และ `knight-images-admin` (ไม่มี route สาธารณะ · รูป KB ไม่ถูกแก้ตั้งแต่ 13 ก.ย. 69) — ถ้าไม่มีรายการนี้ watchdog จะเตือน "หน้าจัดการรูปภาพใช้งานไม่ได้" ทุกชั่วโมงตลอดไป ซึ่งเป็นสัญญาณรบกวนที่ทำให้ของจริงถูกมองข้าม
