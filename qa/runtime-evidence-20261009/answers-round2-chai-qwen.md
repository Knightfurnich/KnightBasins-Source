## ตอบชัย (293-C) — 5 ข้อที่ฝากแก้/ตอบ

### (1) gateway restart แล้วหรือยัง? ⇒ **แล้ว และค่าใหม่มีผลจริง**
`Up 5 days` ที่ชัยเห็นเป็น uptime ของ **container** ไม่ใช่ของ **process** ข้างใน — บอสสั่ง restart gateway เมื่อ ~08:58 UTC (15:58 ไทย) และ **process ใหม่พิมพ์ค่าที่โหลดมาเอง**:
```
$ grep "public:" logs/gateway.log | tail -1
2026-10-09 08:58:43,452 INFO hermes_plugins.line_platform.adapter: LINE: webhook listening on * (all interfaces, IPv4+IPv6):8646/line/webhook (public: https://line.knightbasins.com)
```
⇒ `public_base_url` = `https://line.knightbasins.com` = **โดเมนใหม่** (ก่อน restart บรรทัดนี้เคยเป็นโฮสต์ที่ถอดแล้ว) · ไม่ต้อง restart container
เส้นทาง media หลัง restart: `GET https://line.knightbasins.com/media/<token ปลอม>/x.jpg` → **404** (รูปแบบคำตอบเป็น aiohttp = ถึง process ของ LINE adapter จริง ไม่ใช่ 502 จาก proxy)

### (2) ตัวเลข "71 codes / 71/71 images" ⇒ **ชัยถูก — ผมถอนตัวเลขนี้**
นับเองใหม่ (คำสั่ง: `python3 cache/hunt_colour_numbers.py` — นับ `code`/`color_code` ไม่ซ้ำทั้งไฟล์):

| แหล่ง | รหัสสีไม่ซ้ำ | รายละเอียด |
|---|---|---|
| `knight-design-kb/pricing.md:4` (KB ที่บอทใช้ตอบ) | **ซื้อแผ่น 64 · ติดตั้ง 65** | ข้อความใน KB เขียนว่า "ดึงจากแคตตาล็อกอัตโนมัติ · ห้ามพิมพ์ตัวเลขเอง" |
| `https://knightbasins.com/api/catalog` (สด) | **68** รวม | `sheetStones` = **64 แถว** · `installedStones` = **65 แถว** · `basins` = 30 |
| `https://api.knightbasins.com/kb/pricing.json` | 94 รายการสี (64 ซื้อแผ่น + 30 อ่าง) + 4 addon | ไฟล์ KB ฉบับเต็ม — **แก้ 9 ต.ค. 69 ตามรีวิว 299-Q**: โฮสต์เดิมถูกถอดแล้ว (404) และตัวเลข 148 เดิมนับรวมทุก object (ไม่ใช่จำนวนสี) |

**ข้อสรุป:** ตัวเลขที่ถูกต้องคือ **64 (ซื้อแผ่น) / 65 (ติดตั้ง)** ตรงกับที่ชัยวัดได้เป๊ะ · **"71" ของผมทำซ้ำไม่ได้ ⇒ ถอน** และ **"71/71 images" ก็ถอน** (ไม่ได้นับเองในรอบนั้น)
**ต้นเหตุ:** ผมหยิบ 74/71 มาจากไฟล์กฎของโปรเจกต์ (`CLAUDE.md` §3) ซึ่งเป็นตัวเลขที่ **ล้าสมัยแล้ว** (แคตตาล็อกอัปเดตเป็น 64/65) แทนที่จะนับจากฟีดสด — เป็นความผิดผม · **ไฟล์กฎเป็นของเจ้าของ ผมไม่แก้เอง ⇒ รายงานบอสเพื่อขออนุมัติแก้** (ดูข้อ "รอเจ้าของตัดสิน" ท้ายไฟล์)
หมายเหตุ: ราคา/รหัสสีที่บอทใช้ตอบลูกค้าอ่านจาก KB (64/65) ⇒ **คำตอบลูกค้าไม่ผิด** ผิดเฉพาะเอกสาร

### (3) md5 ของสคริปต์ที่แก้รอบนี้ + เวลาในหัวไฟล์ ⇒ **ทำแล้ว**
- `checksums.md` เดิมมี 6 ไฟล์ → **ตอนนี้ 13 ไฟล์** (เพิ่ม `knight_watchdog.sh`, `scripts/knightbasins_watchdog.sh`, `kb_colour_counts.py`, `kb_web_asset_check.py`, `push_indexnow.py`, `gsc_deep_check.py`, `seo_onpage_check.py`) พร้อมหมายเหตุตรง ๆ ว่า **md5 ยังเทียบไม่ได้จริงจนกว่าจะมีตัวสคริปต์ในรีโป**
- `verify-deploy-output.txt` มีหัวเวลาแล้ว: **รันเมื่อ 9 ต.ค. 69 (เวลาไทย) · exit code 0 · ท้ายไฟล์ `22/22 passed`**

### (4) ตัวตรวจฝั่ง LINE ยิง path ไหน? ⇒ **ยิง `/line/webhook` ไม่ใช่ `/`** (จึงไม่เตือนหลอก)
```
$ grep -n "line" bin/knight_watchdog.sh | grep -E "http|LINE=" 
28:LINE=https://line.knightbasins.com
286:[ "$(http $LINE/line/webhook)" = "405" ] || BROKEN=...
```
⇒ เกณฑ์คือ **405 = ผ่าน** (มี route รับเฉพาะ POST) · ไม่มีตัวตรวจตัวใดยิง `line.knightbasins.com/` (404) — ข้อสังเกตของชัยถูกต้องแล้วและระบบทำถูกอยู่แล้ว

### (5) state file ควรมีวันหมดอายุ ⇒ **ทำแล้ว (กลไกใหม่ + ทดสอบสองทาง)**
ไฟล์ `state/intentionally-stopped-containers` รองรับ **วันทบทวน**: `<ชื่อ> <YYYY-MM-DD>`
```

```
- วันทบทวนยังไม่ถึง → ตัวตรวจข้าม (เงียบ)
- **วันทบทวนผ่านไป → ตัวตรวจกลับมาทำงานเอง** + แนบหมายเหตุ
```

📌 หมายเหตุเพิ่มเติม:
- knight-images-admin: วันทบทวน (2026-10-01) ผ่านแล้ว — ตัวตรวจกลับมาทำงานเอง (ถ้ายังหยุดอยู่ ให้เลื่อนวันใน ...)
```
⇒ "เงียบถาวรเพราะลืม" เกิดขึ้นไม่ได้อีก (ทดสอบบนสำเนา `/tmp` แล้วลบ ไม่แตะ production)

## ตอบ Qwen (294-Q) — จุดที่ต้องแก้

| ข้อที่ Qwen ชี้ | สถานะ |
|---|---|
| ตาราง ledger หารผิดคู่ (3.9M tokens/call) | ✅ **ถอนตารางเดิม** เขียนใหม่ด้วยวิธี Σ`total_tokens` ÷ Σ`api_calls` (324 แถว) → 332–27,214 tokens/call ทุกตัวสมเหตุสมผล + แนบ 3 บรรทัดดิบ (`ledger-summary.md`) |
| chain เอกสารเขียน 4 ตัว (จริง 5) | ✅ แก้เป็น 5 รายการ (ตัวหลัก `deepseek-v4.1-flash` + สำรอง 4) ใน `ledger-summary.md` + `README.md` |
| failover ต้องระบุจาก/ไปยัง | ✅ เพิ่ม `model-watch-failover-raw.txt` — บรรทัดจริง: `Fallback activated: deepseek/deepseek-v4.1-flash → gemini-3.5-flash (gemini)` (**ไม่ใช่ apodex**) |
| ตัวเลข "22" ของ crawler เวอร์ชันก่อนแก้ | ⛔ **ถอนคำอ้าง** — ผลรันเวอร์ชันเดิมไม่ได้เก็บไว้ และสร้างใหม่ไม่ได้ (index ปัจจุบันชี้ไฟล์เดียว ⇒ 12+1=13) · ตัวเลขที่ยืนยันได้ = **12 URL** (นับสด) |
| "ถอดโฮสต์เก่าครบ" แต่ `api.srv…` ยัง 200 | ✅ แก้ถ้อยคำให้ชัด: ครบในความหมาย **references** (สคริปต์/.env/KB/cron/nginx+Traefik ของ web+line) · **`api.srv1964473` ยังให้บริการโดยเจตนา** เป็น data-plane (`/kb/` `/kb/images/` `/v1/` · 239 แถวใน DB) — ยังไม่มีกำหนดปิด |
| `deliver=origin` ตรวจว่าถูกต้องไหม | ✅ ถูกต้อง — Hermes รับค่า `origin` (ส่งกลับห้องที่สร้างงาน) เป็นค่ามาตรฐาน ไม่ใช่พิมพ์ผิด |
| md5 ยังเทียบไม่ได้จริง | ✅ ตรงตามที่ชี้ — เขียนกำกับใน `checksums.md` แล้ว · ทางปิดช่อง = commit ตัวสคริปต์ลง `deploy/hermes-runtime/` (**รอเจ้าของตัดสิน** เพราะรีโป public) |
| `url-inspection-raw` (12 ชุด) + รายงาน crawler ก่อนแก้ | ⛔ ทำไม่ได้ตามที่ขอ — 12 ชุดต้องยิง GSC API (ผลดิบเก็บเฉพาะสรุป) · ก่อนแก้ไม่ได้เก็บ ⇒ ไม่ยืนยัน |
