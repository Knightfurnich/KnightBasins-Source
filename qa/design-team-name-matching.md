# ดีไซน์: จับคู่ชื่อทีมช่างที่เขียนได้หลายแบบ (รวมสะกดผิด)

**ที่มา:** เจ้าของตั้งข้อสังเกตว่าในกลุ่ม LINE เขียนชื่อทีมได้หลายแบบและสะกดผิดได้ด้วย
เช่น `ทีมเจมส์` อาจเขียนเป็น **`ทีมเจม`** (ตัดตัวท้ายออก) · `ทีมออฟฟิศ` / `ทีมออฟฟิต`
วิธีเดิมที่ใช้ alias แบบเป๊ะตัวอักษรจึงมีรูรั่ว

## หลักคิด

**อย่าพยายามเดาให้ครบทุกการสะกด** — เป็นไปไม่ได้และเสี่ยงจับผิดทีม
เป้าหมายจริงคือ **"ไม่มีงานไหนหายเงียบ"** ถ้าจับคู่ไม่ได้ ระบบต้องถามคน ไม่ใช่ทิ้ง

## ข้อมูลจริง (548 ข้อความกลุ่ม · 11–24 ก.ย. 69)

คำที่ตามหลัง "ทีม": เนตร 13 · เจมส์ 9 · ยี่ 8 · ทู 6 · พร้อม 1 · ออฟฟิต 1 · โรงงาน 1 · ช่าง 1
รูปที่เจอจริง: `ทีมเจมส์ครับ.` (คำลงท้าย+จุดเกาะติด) · `ทีมช่าง` (คำว่า "ทีม" ไม่ได้ตามด้วยชื่อทีม)

## อัลกอริทึมที่ทดสอบแล้ว — 4 ชั้น หยุดที่ชั้นแรกที่จับได้

รันได้จริง: `bin/knight_team_match_prototype.py` · replay ทั้งคลัง: `bin/knight_team_match_replay.py`

### ชั้น 0 · Normalize — deterministic ไม่ใช่การเดา
- Unicode **NFC** · ลบ zero-width (`U+200B`–`U+200D`, `U+FEFF`) · ยุบช่องว่างทั้งหมด
- เลขไทย → อารบิก
- ยุบตัวอักษรที่ออกเสียง/หน้าตาใกล้กัน:

| ยุบเป็น | ตัวที่ยุบ |
|---|---|
| ส | ศ ส ษ |
| ต | ต ฏ |
| ท | ท ฑ ฒ ธ |
| น | น ณ |
| ย | ย ญ |
| พ | พ ภ |
| ล | ล ฬ |

- **รูป loose** = รูป normalize แล้วตัดวรรณยุกต์/การันต์ออก (`ั ็ ่ ้ ๊ ๋ ์ ํ ิ ี ึ ื ุ ู`)
  ใช้เทียบคู่กับรูปปกติ — ทำให้ `เจมส` = `เจมส์`

### ชั้น 1 · Alias registry (แอดมินแก้เองได้)
ตาราง `technician_teams.aliases`
⚠️ **เก็บ alias แบบไม่มีคำว่า "ทีม"/"ช่าง" นำหน้า** เช่น `["ออฟฟิศ", "ออฟฟิต", "แอนนี่"]`
เพราะตัวจับคู่ตัดคำนำหน้าออกแล้วเทียบทีละคำ — ถ้าเก็บ `"ทีมออฟฟิศ"` จะไม่ตรงกับ token `"ออฟฟิศ"`

### ชั้น 2 · Prefix + Fuzzy — มี guard กันพลาด
- **ตัดคำนำหน้า + เครื่องหมายวรรคตอน + คำลงท้ายก่อน** (`ครับ` `ค่ะ` `คะ` `นะ` `จ้า` `ด้วย`)
  ⚠️ ลำดับสำคัญ: ตัดเครื่องหมายวรรคตอน **ก่อน** ตัดคำลงท้าย ไม่งั้น `เจมส์ครับ.` ไม่ถูกตัด
- **Prefix match** (จับ `ทีมเจม` → เจมส์): ยอมรับถ้า token เป็นคำนำหน้าของชื่อ และ
  **ความยาว token (รูป normalize) ≥ 3 ตัว**
  ⚠️ guard ต้องวัดจากรูป normalize ไม่ใช่รูป loose ไม่งั้น `ชัย` → loose `ชย` (2 ตัว) ตก guard
- **Fuzzy match**: เฉพาะชื่อยาว **≥ 4 ตัวอักษร** และต่างกัน ≤ 1 ตัว
  ชื่อสั้น 2–3 ตัว (`ยี่ ทู เปา ชล อ้น เอก`) **บังคับตรงเป๊ะเท่านั้น**
- ผลจากชั้นนี้ **ติดธง confidence ต่ำ** ไม่ใช่ค่าที่เชื่อได้ทันที

### ชั้น 3 · Unmatched queue — ชั้นที่สำคัญที่สุด
ข้อความที่มีคำว่า `ทีม`/`ช่าง` + รหัสงาน (`JB…` / `26/…`) แต่จับทีมไม่ได้ → **ห้ามทิ้ง**
เข้าเป็นรายการ **"รอระบุทีม"** ในหน้าแอดมิน พร้อมข้อความดิบ และมี 2 ปุ่ม:

- **ระบุทีม** → บันทึกวลีนั้นเป็น `aliases` ของทีมนั้น ถาวร
- **ไม่ใช่ทีม (ข้าม)** → บันทึกวลีนั้นเป็น `ignore_phrases` ถาวร เช่น `ช่างอ๊อก` `แบบช่าง`
  (เป็นคู่ค้า/ช่างเชื่อม/แบบร่าง ไม่ใช่ทีมติดตั้ง)

**เปลี่ยนปัญหา "ต้องเดาให้ครบ" เป็น "ถามครั้งเดียวแล้วจำ"**

### ชั้น 4 · ความกำกวมและการเปลี่ยนทีม
- ข้อความที่มี 2 ทีมขึ้นไป (`เปลี่ยนจากทีมเจมส์เป็นทีมเนตร`) — **ห้ามใช้ "เจอตัวแรกก่อน"**
  ถ้ามี `เปลี่ยน`/`เป็น`/`จาก` → เลือกทีมที่อยู่ **หลังคำว่า "เป็น"** ถ้าแยกไม่ได้ → เข้า queue
- เก็บ `technician_team_match_confidence` = `exact | alias | prefix | fuzzy | manual`
  ให้แอดมินกรองดูเฉพาะ `prefix`/`fuzzy` มาขึ้นยัน

## บั๊ก 3 จุดที่เจอตอน prototype (ต้องระวังตอน implement จริง)

1. **Alias เก็บพร้อมคำนำหน้า** → `ทีมออฟฟิศ` ไม่ตรงกับ token `ออฟฟิศ` — ต้องเก็บแบบไม่มีคำนำหน้า
2. **ลำดับการตัดคำ** → ตัดเครื่องหมายวรรคตอนก่อนคำลงท้าย ไม่งั้น `เจมส์ครับ.` ไม่ถูกตัด
3. **Guard ความยาวผิดรูป** → วัดจากรูป loose ทำให้ `ชัย` (→`ชย`) ตก guard ทั้งที่ควรเป็น prefix ของ `ชัยยา`
