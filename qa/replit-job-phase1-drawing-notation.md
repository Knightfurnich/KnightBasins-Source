# ใบงาน Replit — เฟส 1: แบบผังให้เหมือนแบบเขียนมือ + คิดบัว/ขอบเป็นเมตร
สร้าง 15 ก.ย. 2026 · แอป Knight Basins · repo Knightfurnich/KnightBasins-Source

## ที่มา (ผู้ใช้อนุมัติแล้ว)
แบบที่ช่างใช้จริงเป็นแบบเขียนมือ มีสัญลักษณ์และเส้นบอกขนาดครบทุกด้าน ใช้คำนวณพื้นที่และราคา
ตัวเลขตัวอย่างที่ตกลงกัน (ห้ามแก้): ชิ้นงานล่างรูป L = 2.8458 ตร.ม. · ชิ้นงานบน (ฐาน) = 1.5504 ตร.ม. · รวม 4.3962 ตร.ม.
แนวติดตั้งบัวยาวรวม 4.08 ม. · ขอบ (วงกลมกากบาท) ยาวรวม 4.59 ม. · ขนาดขอบ = 24/30 มม. · **ขนาดบัวยังไม่ระบุ**

## ความหมายของสัญลักษณ์ (ต้องวาดให้ตรงนี้)
| สัญลักษณ์ | ความหมาย | มีผลต่อราคา |
|---|---|---|
| ▲ สามเหลี่ยม | ติดตั้งบัวตลอดแนวนั้น | ใช่ — คิดเป็นเมตร |
| ⊗ วงกลมกากบาท | ขอบเปิดโชว์ตามแนวนั้น (ขนาด 24/30 มม.) | ใช่ — คิดเป็นเมตร |
| ขีดคู่ | ด้านเท่ากัน และชิดผนัง/กำแพง ไม่ใช่ขอบเปิดโชว์ | ไม่มีผลต่อราคา (ทำเครื่องหมายเท่านั้น) |
| เส้นประ | แนวฉาก / แนวต่อแผ่น | ไม่มีผลต่อราคา |
| เส้นบอกขนาด | เขียนครบทุกด้าน (มม.) | ไม่มีผลต่อราคา |

## งาน A: ปรับหน้าตาแบบผัง (ใช้ทั้งหน้า Studio, หน้า saved quote, ไฟล์ DXF และหน้า PDF/พิมพ์)
1. **เขียนเส้นบอกขนาดครบทุกด้าน** ตามที่กรอก (A / B / C / ความลึก) แบบที่ช่างอ่านแล้ววัดได้ทันที
2. **เลือก▲-⊗-ขีดคู่ ได้ทีละด้าน** (ต่อขอบของรูปทรง) — ไม่ใช่ติ๊กครั้งเดียวทั้งผังแบบปัจจุบัน
3. วาดสัญลักษณ์ให้ถูกตำแหน่งและอ่านง่าย: ▲ บนแนวนั้น · ⊗ บนแนวนั้น · ขีดคู่บนด้านชิดผนัง
4. **ตัดเส้นระยะขอบ 50 มม. ออก** จากแบบที่ผู้ใช้/ช่างเห็น (ยังคงใช้ตรวจความปลอดภัยภายใน และบล็อกการส่งเหมือนเดิม)
5. **ลากเส้นประแนวต่อแผ่น** ตามแนวฉาก (ใช้จุดที่รู้อยู่แล้วว่าเกินแผ่นมาตรฐาน 0.76 × 3.60 ม.)
6. แสดงป้ายขนาดขอบ (24/30 มม.) และป้ายบัว — ถ้าขนาดบัวยังไม่ถูกกำหนด ให้เว้นว่าง/แสดง "ยังไม่ระบุ" **ห้ามใส่ตัวเลขเดา**

## งาน B: ตั้งค่าด้านต่อด้าน — ทำเป็น 2 โหมด (ผู้ใช้อนุมัติแล้ว)
| โหมด | ใครใช้ | พฤติกรรม |
|---|---|---|
| **โหมดด่วน (ค่าเริ่มต้น)** | ลูกค้าทั่วไป | เลือกรูปทรง + ขนาด + ติ๊ก "มีบัวด้านหลัง" เหมือนเดิมเป๊ะ — **ไม่ต้องเลือกทีละด้าน** |
| **โหมดละเอียด** | ทีมขาย / งานที่ต้องส่งช่าง | เปิดให้เลือก ▲ / ⊗ / ขีดคู่ ทีละด้าน + กรอกความสูงบัว + ราคาขอบ/เมตร |

- ค่าเริ่มต้นต้องเป็น**โหมดด่วน** — ห้ามเปลี่ยนพฤติกรรมเดิมของลูกค้าที่เคยใช้ (ลดความเสี่ยงและไม่ต้องสอนใหม่)
- สลับไปโหมดละเอียดได้ตลอด และกลับมาโหมดด่วนได้ (ค่าในโหมดละเอียดถูกเก็บไว้ ไม่หาย)
- ทั้งสองโหมดต้องออกใบเสนอราคาได้เหมือนกัน และยังใช้กฎราคาเดิมทุกข้อ
- เก็บค่าใน studioData: โหมดที่ใช้ · ด้านไหนมีบัว · ด้านไหนเป็นขอบเปิด · ด้านไหนชิดผนัง
- คำนวณความยาวรวม: แนวบัว (ม.) และ ขอบเปิด (ม.)
- บันทึกติดไปกับใบเสนอราคา และแสดงในข้อความ Telegram เช่น "บัว 4.08 ม. · ขอบ 4.59 ม."

**หมายเหตุสำคัญ:** ใบเสนอราคาเก่าที่บันทึกไว้แล้ว **ห้ามคิดเงินใหม่** — ใช้ snapshot เดิมเสมอ (ตัวเลขของใบเก่าต้องไม่เปลี่ยน)

## งาน C: คิดราคาบัว/ขอบ (แก้ไขตามที่ผู้ใช้ยืนยันล่าสุด)
| รายการ | หน่วยคิดเงิน | ราคา |
|---|---|---|
| หิน (เคาน์เตอร์) | ตร.ม. | เรตหินของสีที่เลือก (ตามเดิม) |
| **บัว** | **ตร.ม.** | จากความยาวแนวบัว × ความสูงบัว (ผู้ใช้/ทีมขายกรอกความสูง) |
| **ขอบเปิด (⊗)** | เมตร | ราคาต่อเมตร — **ทีมขายกรอกเอง** (ค่าเริ่มต้นว่าง ห้ามใส่เลขให้เอง) |

1. **ความสูงบัวต้องกรอกได้และต้องไม่เป็นค่าว่าง** — เพราะขนาดบัวยังไม่ระบุ ห้ามระบบเดาตัวเลขให้เอง
   ถ้าไม่ได้กรอกความสูง → ยังคิดเงินบัวไม่ได้ และต้องขึ้นข้อความ "ยังไม่ได้ระบุความสูงบัว"
2. พื้นที่ที่คิดเงิน = พื้นที่เคาน์เตอร์ + พื้นที่บัว (ความยาวแนวบัว × ความสูงบัว)
3. ราคาต่อ ตร.ม. ของบัว: ถ้ามีช่อง "ราคาบัว/ตร.ม." ที่กรอกเอง ให้ใช้ค่านั้น · ถ้าไม่กรอก ให้ใช้เรตหินของสีที่เลือก
   **(ยืนยันกับผู้ใช้ก่อน implement ว่าต้องการแบบไหน)**
4. ราคาขอบต่อเมตร: ช่องกรอกเอง ค่าเริ่มต้นว่าง = ไม่คิดเงิน + ขึ้นข้อความ "ยังไม่ได้กรอกราคาขอบ"
5. สรุปยอดในใบเสนอราคาแยกบรรทัด: หิน (เคาน์เตอร์ × เรต ตร.ม.) · บัว (พื้นที่บัว × เรต ตร.ม.) · ขอบเปิด (ความยาว × ราคา/ม.) · อ่าง + ค่าติดตั้ง · ค่าดำเนินการงานพื้นที่เล็ก · VAT
6. **ห้ามแตะกฎเดิม**: ห้ามหักพื้นที่ช่องเจาะอ่าง · อ่างคิดเป็นใบ · ค่าติดตั้ง 5,000/ชุด ฟรีเมื่อ 3 ชุด

**หมายเหตุ:** ด้านชิดผนัง/ขีดคู่ ไม่มีผลต่อราคา (แสดงเป็นเครื่องหมายให้ช่างอ่านเท่านั้น)

## กติกาบังคับ (แก้ช่องโหว่สเปก 14 ข้อ — ห้ามตีความเอง)
1. **แหล่งข้อมูลหลัก = สถานะรายด้านของผัง** — ตัวเลข 4.3962 / 4.08 / 4.59 ใช้เป็น**เคสทดสอบเท่านั้น** ห้าม hard-code เป็นค่าจริงในโค้ด
2. **หนึ่งด้านมีสถานะเดียวเท่านั้น**: ชิดผนัง / ติดบัว / ขอบเปิดโชว์ / ปกติ (ห้ามเลือกซ้อนกัน เพื่อกันคิดเงินซ้ำ)
3. **ชิดผนัง = ไม่คิดเงิน** และห้ามถูกนับเป็นขอบเปิดโดยเด็ดขาด
4. **ความสูงบัวว่าง** → ยังออกใบเสนอราคาได้ แต่ไม่คิดเงินบัว และต้องแสดงคำเตือน "ยังไม่ได้ระบุความสูงบัว" ติดไปกับใบ (ไม่บล็อกทั้งใบ)
5. **ราคาขอบ**: ว่าง = ยังไม่กรอก → แสดงคำเตือน · 0 = ตั้งใจให้ฟรี → แสดง "ฟรี" ไม่ต้องเตือน · ค่าติดลบ = ห้ามกรอก · รองรับทศนิยม 2 ตำแหน่ง
6. **เส้นประแนวต่อแผ่น = เส้นไกด์เท่านั้น** ไม่มีผลต่อพื้นที่หรือราคา · วางที่ทุก 3.60 ม. ของแต่ละแนว (แยกด้าน ไม่หมุนแผ่น) · เฟสนี้ยังไม่ให้ลากเอง · ต้องมีตัวเลขระยะกำกับ
7. **เส้น 50 มม. ต้องไม่ปรากฏ** ในทุกช่องทางที่ผู้ใช้/ช่างเห็น: Studio · saved quote · งานพิมพ์ · PDF · DXF · ภาพตัวอย่าง · Telegram และต้องมีเทสต์ตรวจ DXF ว่าไม่มีเส้น/เลเยอร์นี้ (ยังคงใช้ตรวจความปลอดภัยและบล็อกการส่งภายใน)
8. **Snapshot ใบเสนอราคา** ต้องเก็บให้ครบและหน้าใบเสนอราคาอ่านจาก snapshot เท่านั้น ห้ามดึงราคาปัจจุบันจากฐานข้อมูล:
   พื้นที่ · ความยาวบัว · ความสูงบัว · ความยาวขอบ · ราคาหิน · ราคาบัว · ราคาขอบ · ค่าติดตั้ง · ค่าดำเนินการงานพื้นที่เล็ก · VAT · ยอดรวม · ข้อความเตือน
9. **โหมดด่วน ↔ ละเอียด**: เข้าโหมดละเอียดให้ยึดค่ารายด้านเป็นหลัก · กลับโหมดด่วนให้สรุปเป็น "มี/ไม่มีบัวด้านหลัง" โดย**ไม่ลบค่ารายด้านเดิม** · ต้องระบุให้ชัดว่า "ด้านหลัง" = ด้านไหนของแต่ละรูปทรง
10. **รอยบาก/ขั้น ยังไม่รองรับในเฟสนี้** — วาดเฉพาะสี่เหลี่ยมฐาน และต้องขึ้นข้อความเตือนบนหน้าจอว่า "ยังไม่รองรับรอยบาก/รูปทรงอิสระ (เฟส 2)" เพื่อไม่ให้ทีมขายเข้าใจว่าแบบครบ · พื้นที่คิดจากฐานเท่านั้น
11. **หลายชิ้นงาน: เฟสนี้ 1 ใบ = 1 ชิ้นงาน** + แสดงข้อความเตือนแบบเดียวกับข้อ 10
12. **เลเยอร์ DXF เพิ่มใหม่**: `UPSTAND` (▲) · `OPEN_EDGE` (⊗) · `WALL_FLUSH` (ขีดคู่) · `JOINT` (เส้นประ) และเทสต์เดิมต้องยังผ่านครบ ($INSUNITS = 4 · NOTE ASCII · เลเยอร์เดิม 6 ชื่อ)
13. **บอท LINE / เครื่องคิดราคาฝั่งเรา**: ห้ามตอบราคาบัว/ขอบจาก KB เพราะยังไม่มีเรต — ถ้าลูกค้าถาม ให้ตอบว่า "ทีมขายจะคิดให้" (ฝั่งเดวิดจัดการเอง)
14. **ใบที่ไม่มีบัว/ขอบเลยต้องออกได้ตามปกติ** — ห้ามบังคับให้ต้องตั้งค่าทุกด้าน (งานด่วนต้องไม่พัง)

## กติกาบังคับรอบ 2 (ช่องโหว่ที่เดวิดพบเพิ่ม — ต่อจากข้อ 14)
15. **เปลี่ยนรูปทรง (I → L → U) ต้องจัดการค่าที่ตั้งรายด้านยังไง** — จำนวนด้านเปลี่ยน (L มี 5 ด้าน · U มี 6 ด้าน) ให้ **รีเซ็ตสถานะรายด้านกลับเป็นค่าเริ่มต้น พร้อมแจ้งเตือนบนหน้าจอ** ว่า "เปลี่ยนรูปทรงแล้ว ค่าที่ตั้งรายด้านถูกล้าง" · แต่ **เปลี่ยนขนาด (A/B/C/ความลึก) ต้องไม่ล้างค่า** (ด้านยังเป็นด้านเดิม)
16. **นิยาม "ด้าน" และความยาวของแต่ละด้าน (สำคัญที่สุด — ตัวเลข 4.59 มาจากข้อนี้)**
   - หนึ่ง "ด้าน" = ช่วงเส้นตรงระหว่างมุมสองมุม
   - ด้านที่ถูกใช้ร่วมกัน 2 ขา (ช่วงมุมทับ) **นับครั้งเดียว** — สถานะก็ตั้งครั้งเดียว
   - ความยาวขอบเปิด = ผลรวมด้านที่ตั้งเป็น ⊗ เท่านั้น (ไม่รวมด้านชิดผนัง/ด้านติดบัว) → ตรงกับ 3170 + 1420 = 4.59 ม.
   - ความยาวแนวบัว = ผลรวมด้านที่ตั้งเป็น ▲ เท่านั้น → ตรงกับ 2040 + 2040 = 4.08 ม.
17. **การคำนวณเงินต้องใช้ค่าละเอียด** — ห้ามคูณด้วยค่าที่ปัดแล้ว (พื้นที่/ความยาว) ให้คูณด้วยค่าจริง แล้วปัดเป็นจำนวนเต็มบาท**ครั้งเดียวตอนแสดงผลเป็นเงิน** ไม่งั้นยอดจะคลาดเคลื่อนสะสม
18. **ค่าดำเนินการงานพื้นที่เล็กนับจากพื้นที่อะไร** — (รอผู้ใช้ยืนยัน) เคาน์เตอร์เท่านั้น หรือ เคาน์เตอร์ + บัว
19. **ด้านที่ชิดผนัง — กฎระยะ 50 มม. ของอ่างยังใช้กับด้านนั้นไหม** — (รอผู้ใช้ยืนยัน) เดวิดเสนอว่า **ยังใช้ทุกด้าน** เหมือนเดิม เพื่อความปลอดภัยในการเจาะ

## เกณฑ์ตรวจรับ (แนบหลักฐานจริงทีละข้อ)
1. ผังทรง L ที่ตั้งค่า: บัวบนด้านหนึ่ง · ขอบเปิดบนอีกด้าน · ด้านชิดผนัง — วาดสัญลักษณ์ถูกตำแหน่ง (แนบภาพ Studio + saved quote)
2. ไม่มีเส้น 50 มม. ในแบบที่ดาวน์โหลด/พิมพ์แล้ว (แนบภาพ DXF หรือ PDF)
3. เส้นบอกขนาดครบทุกด้าน (แนบภาพ)
4. มีเส้นประแนวต่อแผ่นเมื่อความยาวเกิน 3.60 ม. (แนบภาพ)
5. ความยาวที่คำนวณได้ถูกต้องตามที่ตั้งค่า — ทดสอบเคสตัวอย่าง: บัว 4.08 ม. · ขอบ 4.59 ม. (แนบภาพ)
6. กรอกราคาบัว 500 บาท/ม. และขอบ 300 บาท/ม. → ยอดในใบเสนอราคาเปลี่ยนถูกต้อง และบวกเป็นบรรทัดแยก (แนบภาพ)
7. ไม่กรอกราคา → ไม่คิดเงิน และขึ้นข้อความว่ายังไม่ได้กรอกราคา (แนบภาพ)
8. พื้นที่ที่คิดเงินไม่รวมบัวแล้ว (เทียบตัวเลขก่อน/หลัง) (แนบภาพ)
9. ข้อความ Telegram แสดงความยาวบัว/ขอบที่ตั้งไว้ (แนบภาพ)
10. เทสต์ทั้งหมดผ่าน + build/asset guard ผ่าน (แนบผลรัน)

**ห้าม deploy production เอง** — push ขึ้น GitHub branch main (source + tests + deploy/ + api-dist/ + web-dist/) พร้อมแจ้ง commit + SHA-256
