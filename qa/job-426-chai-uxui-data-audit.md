# ใบงาน 426-C (ชัย) — **ตรวจ UX/UI ของ Knight Basins · มุมข้อมูลและสถานะที่แอปแสดง** (อ่านอย่างเดียว)

**วันที่:** 10 ต.ค. 69 · **ออกโดย:** เดวิด · **เจ้าของงาน:** **ชัย** · **ผู้ตรวจรับ:** **บอส**
**ที่มา:** บอสสั่ง 10 ต.ค. 69 — "ออกใบงานให้ชัย รีพิต และบอย ตรวจสอบการทำงานของ Knight Basins ทั้ง UX/UI"
**การแบ่งงาน (ห้ามทับกัน):** ชัย = เนื้อหา/ข้อมูล/สถานะที่ UI ต้องแสดง (มุม API) · รีพิต = โครงหน้า/การจัดวาง/การเข้าถึง · บอย = คอมโพเนนต์ที่โต้ตอบ (แชท/กล่อง/ฟอร์ม/แอดมิน)
**สถานะ:** อ่านอย่างเดียว — **ไม่แก้โค้ด/ไม่ commit** (ข้อเสนอให้เดวิดออกใบแยก)

```
✅ มาตรฐานการออกใบงาน · 12/12 · 10 ต.ค. 69 · เดวิด

GOAL:
  หา "จุดที่ผู้ใช้จะสับสน/เสียเวลาหรือเสียโอกาสขาย" ที่มีต้นเหตุจากข้อมูลหรือสถานะที่ API ส่งให้หน้าเว็บ
  — ไม่ใช่ความเห็นเรื่องความสวย แต่เป็นสิ่งที่วัดได้และชี้ไฟล์/บรรทัดได้

  A. **ความครบของข้อมูลที่หน้าเว็บต้องใช้** — เดินทีละหน้า (/, /stone, /portfolio, /quote, /price-guide, /readme)
     แล้วจดว่ามีข้อมูลไม่ครบ/ไม่ขึ้น/ขึ้นเป็นค่าว่าง หรือข้อความ fallback (เช่น "ติดต่อทีมงาน", "-") ที่ผู้ใช้เห็น
     โดยอ้าง `GET /api/catalog` และฟีดที่หน้าเว็บเรียกจริง
  B. **สถานะของ UI ที่มาจาก API**: กำลังโหลด · ไม่พบข้อมูล (empty) · ผิดพลาด (error) · ไม่มีสิทธิ์/ยังไม่ล็อกอิน
     — มีครบทุกเส้นทางไหม (ค้นหาสินค้าไม่พบ · สีที่ถูกซ่อน · ใบเสนอราคาหมดอายุ · LINE ยังไม่ล็อกอิน)
     และข้อความที่ผู้ใช้เห็นบอกทางออกจริงหรือไม่
  C. **ฟอร์มและข้อความตรวจสอบ**: ใบขอราคา/สตูดิโอ/สเก็ตช์ — ป้ายช่องกรอก ป้ายบังคับ ข้อความ error
     และข้อความยืนยัน บอกผู้ใช้ถูกต้อง + **ตัวเลข/หน่วย/VAT ที่แสดงตรงกับ KB และแคตตาล็อกสด**
  D. **ความเร็วที่มีผลกับความรู้สึก**: เวลาตอบของ API ที่หน้าแรก/หน้าแค็ตตาล็อกเรียก (วัดจริง 3 รอบ)
     และระบุจุดที่ทำให้ปุ่มค้าง/รอโดยไม่มีสัญญาณให้ผู้ใช้รู้
  E. **ความสอดคล้องของถ้อยคำที่มาจากข้อมูล** (หน่วย ตร.ม./แผ่น/ชุด · การเขียนราคา · ชื่อสี · ชื่อรุ่น)
     และจุดที่ข้อมูลกับข้อความบนหน้าขัดกัน
  F. **ห้ามแก้ไฟล์ใด ๆ** (อ่าน/วัด/แนบหลักฐานเท่านั้น)

SCOPE (อ่าน/วัดเท่านั้น — ห้ามแก้):
  - https://knightbasins.com/ · /stone · /portfolio · /quote · /price-guide · /readme  (production)
  - https://knightbasins.com/api/catalog · /kb/pricing.json · /api/auth/line/status     (ข้อมูลสด)
  - (รีโป) artifacts/api-server/src/routes/ · /opt/data/cache/kbsrc/artifacts/api-server/src/lib/
  - (รีโป) artifacts/knight-basins/src/data/ · /opt/data/cache/kbsrc/artifacts/knight-basins/src/data/
  - /opt/data/cache/kbsrc/artifacts/api-server/test/                                    (เทสต์ที่มีอยู่ อ่าน)
  - /opt/data/knight-design-kb/qa/report-chai-round12-uxui-data-20261010.md             (ใหม่) รายงานของคุณ

FORBIDDEN:
  - ห้ามแก้โค้ด/ไฟล์/คอนฟิก/ฐานข้อมูล · ห้าม commit/push/merge/เปิด PR · ห้ามลบหรือยิง mutation ใด ๆ
  - ห้ามล็อกอินด้วยบัญชีลูกค้าจริง · ห้ามส่งฟอร์มจริง (ห้ามสร้างลีด) · ห้ามใช้ข้อมูลลูกค้า/เบอร์ลูกค้าในรายงาน
  - ห้ามพิมพ์ค่า secret · ห้ามเดาตัวเลข — ทุกตัวเลขต้องมาจากการวัดจริงหรือจาก API/KB
  - ถ้าตรวจไม่ได้ ให้เขียน "ตรวจไม่ได้ + เหตุผล" ห้ามเดา

EVIDENCE (ต้องแนบผลจริง — คำสั่ง/ผลรัน/ตัวเลข/ภาพ):
  **baseline ปัจจุบัน (วัด 10 ต.ค. 69):** `GET /api/catalog` → `sheetStones` 64 · `installedStones` 65 · `basins` 30 · VAT 7% · คำตอบ guest ≤ 4 บรรทัด/≤ 340 ตัวอักษร (เกณฑ์ใหม่จาก #484) ⇒ ใช้เทียบว่าหน้าเว็บแสดงตรงกับตัวเลขชุดนี้ไหม
  0) คำสั่งที่ใช้จริง: `git log --oneline -1` · `git status --short` (ต้องว่าง) · `curl -s -o /dev/null -w "%{http_code} %{time_total}s" <url>` · ตรวจด้วย Chrome DevTools Protocol (แนบสคริปต์ที่ใช้)
  1) ทุกข้อความที่อ้าง: แนบ `curl -s -o /dev/null -w "%{http_code} %{time_total}s"` ของ endpoint ที่เกี่ยว
  2) ตาราง A–E: หน้า/สถานะ · สิ่งที่ผู้ใช้เห็น · หลักฐาน (HTTP/ไฟล์/บรรทัด) · ระดับความรุนแรง (สูง/กลาง/ต่ำ)
  3) ข้อ C: ตัวอย่างข้อความ error/ยืนยันจริง 3 ตัวอย่าง + เทียบตัวเลขกับ `GET /api/catalog` (VAT 7 · เรต · ราคา)
  4) ข้อ D: ตารางเวลา 3 รอบต่อหน้า (`curl -w "%{time_total}"`) + ค่าเฉลี่ย
  5) **อย่างน้อย 5 ข้อค้นพบ** เรียงตามความรุนแรง พร้อมข้อเสนอ (ไม่แก้เอง) — รวมข้อที่ "หลงลืม/ไม่มีเลย" เช่น สถานะว่างที่ไม่มีข้อความ
  6) ระบุ commit/วันที่ของ production ที่ตรวจ (จาก CI ล่าสุด) + เวลาไทยที่ทำ

OUTPUT:
  - `/opt/data/knight-design-kb/qa/report-chai-round12-uxui-data-20261010.md` (ไฟล์เดียวในเครื่องตัวเอง)
  - สรุป 5 บรรทัด: พบอะไร · รุนแรงสุด 3 ข้อ · ตรวจไม่ได้อะไร · ความเสี่ยง · ข้อเสนอ
  - **ไม่ต้องเปิด PR** (ใบนี้ไม่มีการแก้โค้ด) — ส่งรายงานให้บอสเพื่อส่งต่อเดวิด

STOP:
  - ครบ A–E พร้อมหลักฐาน · หรือทำครบ **12 turns** ให้หยุดและรายงานสิ่งที่ทำเสร็จ + ที่เหลือ
  - **ถ้าพบว่าต้องแก้ไฟล์เพื่อยืนยันผล → หยุดทันทีและเขียนในรายงาน** (ใบนี้ห้ามแก้)
```
