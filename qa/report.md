## 1 · draft บันทึกแล้วเปิดกลับไม่ได้ — High / UX

**URL:** /design [2]
**สิ่งที่ผู้ใช้เห็น:** กด "บันทึกการแก้ไข" ขึ้น "บันทึกการแก้ไขแล้ว"

**สิ่งที่ตรวจพบ**

ข้อมูลถูกบันทึกจริง — ทุกคำขอสำเร็จ:
```
POST  /api/quotes/drafts                    -> 201 สร้าง quoteId ad1f550b-...
GET   /api/quotes/ad1f550b-.../draft        -> 200
PATCH /api/quotes/ad1f550b-.../draft        -> 200 บันทึกค่าที่แก้
GET   /api/quotes/ad1f550b-.../draft        -> 200
```

แต่เปิดหน้ากลับมาได้ค่าเริ่มต้นเสมอ:
```
ก่อนบันทึก : ชื่อ QA-PERSIST-7742 · สี SG 420 · ขนาด 0.60 x 1.80
หลังเปิดใหม่: ชื่อ ครัวบ้านใหม่   · สี BW010  · ขนาด 3.8 x 0.65
ปุ่มให้เปิด draft เก่า: ไม่มี (พบเฉพาะ "บันทึกเป็น draft")
URL: /design (ไม่มี quote id)
```

**ผลกระทบ:** คำโฆษณาบนหน้าเว็บว่า *"ทุกการแก้ไขถูกบันทึกเป็น draft ที่ตรวจสอบย้อนกลับได้"* —
ข้อมูลอยู่จริงแต่ลูกค้าเอากลับมาใช้ไม่ได้ ต้องเริ่มใหม่ทุกครั้ง

**ขั้นตอนทำซ้ำ**
1. เปิด /design
2. แก้ชื่อโปรเจกต์ + เลือกสี SG 420
3. กด "บันทึกเป็น draft" → "บันทึกการแก้ไข" (ขึ้นว่า "บันทึกการแก้ไขแล้ว")
4. โหลดหน้า /design ใหม่ → ค่ากลับเป็นค่าเริ่มต้น

**ที่ควรเป็น:** มีทางกลับเข้า draft ที่บันทึกไว้ — เช่น `/design?quote=<id>`
หรือรายการ draft ที่เปิดได้จากหน้าแรก (ตอนนี้หน้าแรกมี card "DRAFT / 04—25"
แต่ปุ่มชี้ไป /design ซึ่งเริ่มใหม่)

## หมายเหตุการตรวจ

- บันทึกไว้ก่อนหน้าแล้วว่า "draft ไม่ถูกบันทึก" — **ข้อสรุปนั้นผิด**
  ข้อมูลถูกบันทึกจริง (201/200 ทุกคำขอ) ปัญหาคือเปิดกลับมาไม่ได้
- การตรวจบางส่วนรันอัตโนมัติด้วยตัวตรวจที่เขียนไว้สำหรับงานนี้ [3]
- ไม่ได้ทดสอบ: pinch zoom บน LINE WebView · LINE Login จริง ·
  การส่ง draft ให้ทีมขายปลายทาง
- ข้อจากัดของรายงานนี้: sentence จำนวนมากเป็นผลลัพธ์คำสั่งแบบคำต่อคำ
  (ใน code block) ซึ่งตัวนับ coverage ไม่นับ — จึงอ่านที่ "citations OK"
  และรายการ warning ไม่ใช่ที่เปอร์เซ็นต์ coverage
