## 5 · กระบวนการส่งงาน

1. อ่านใบงานให้ครบ (GOAL · SCOPE · FORBIDDEN · EVIDENCE · OUTPUT · STOP)
2. ตั้งชื่อสาขา: `feat/freebuff-<เรื่อง>` หรือ `fix/freebuff-<เรื่อง>`
3. ทำตาม SCOPE เท่านั้น · เคารพ FORBIDDEN · หยุดตามเงื่อนไข STOP (ถ้าใกล้ชนเพดาน ให้หยุดแล้วรายงานสิ่งที่เสร็จ + ที่เหลือ)
4. แนบหลักฐานจริงครบทุกข้อใน EVIDENCE (คำสั่ง + ผลรัน + ตัวเลข + ภาพหน้าจอ/ค่าจาก DOM ถ้าเป็น UI)
5. เปิด PR เข้า `main` → **อย่า merge เอง** → ส่งลิงก์ให้เดวิดและบอส

## 6 · หน้าที่ตรวจงานอิสระ (Independent Verification)

เมื่อมี PR จากชัย/คนอื่น ให้ตรวจซ้ำอีกชั้นก่อนถึงบอส — **ห้ามเชื่อคำสรุป ให้ดูของจริง**

- รันเทสต์ + typecheck ด้วยตัวเอง แล้วเทียบตัวเลข baseline ที่ PR อ้าง
- **ยิงของจริง** ตามเส้นทางที่ผู้ใช้ใช้ (เปิดหน้าจริง/ยิง API จริง) ไม่ใช่แค่อ่านโค้ด
- วัดค่าจาก DOM/HTTP ไม่ใช่การมองด้วยตา: เช่น นับ element ที่ซ้อนกัน, อ่าน `content-type`, อ่านรหัส HTTP
- ระบุ pass/fail **ทีละข้อพร้อมหลักฐานดิบ** (รหัส HTTP, ตัวเลข, ข้อความที่พบ)
- ถ้าพบว่าไม่ตรงกับที่ PR อ้าง → รายงานทันทีพร้อมหลักฐาน ห้ามสรุปว่า "ผ่าน" เพื่อความเรียบร้อย
- ตัวอย่างที่เคยพลาดจริง: เทสต์เขียว 100% แต่โมเดล AI ที่ฝังไว้ไม่มีอยู่จริง (เทสต์ mock ไว้) · การ์ดแสดงค่าผิดเพราะชนิดข้อมูลไม่ตรง (string vs number)
