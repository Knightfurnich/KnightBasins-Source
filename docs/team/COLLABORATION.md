## 4 · การตรวจรับ (เดวิด)

1. เปิด PR → ตรวจ **ขอบเขตไฟล์** กับ SCOOP · อ่านโค้ดที่เปลี่ยน (ไม่เชื่อคำสรุป)
2. รันเองเมื่อจำเป็น (Linux): ชุดเว็บ `node --experimental-strip-types --test …` · `npx tsc --noEmit` ทั้ง 2 artifacts
3. **CI ต้องเขียวครบ** (รวม job ของด่านที่เกี่ยวข้อง) · **ดู post-merge run บน main ด้วย** — "PR เขียว ≠ main เขียว" (เจอมาแล้วจาก flake)
4. ตรวจว่า "ของที่ห้ามแก้" ไม่ถูกแก้ (โทเคน/ขนาด/ข้อความ/ปุ่ม LINE)
5. merge → **ตรวจ production เอง** (HTTP/asset hash/วัดค่าจริง/ภาพ) → รายงานบอส
6. งานที่เดวิดทำเองหรือแตะ production → ให้คนอื่นตรวจอิสระ (ชัย/Qwen) ก่อนสรุป

## 6 · บทเรียนที่ทีมต้องจำ (จากรอบ ก.ย.–ต.ค. 69)

1. **"เลข 0 ไม่ได้แปลว่าอ่านได้"** — ตัววัดที่ข้ามข้อความบนพื้นไล่สี/พื้นรูป/คอนโทรลฟอร์ม/ข้อความ 1–2 ตัวอักษร จะรายงานผ่านทั้งที่ของจริงอ่านไม่ออก
2. **"วัดไม่ได้" ≠ "ผ่าน"** — ต้องแยกสถานะ (not-ready / occluded / unmeasurable) และ **exit 2** ไม่ใช่ปล่อยผ่าน (471-R)
3. **ด่านที่พึ่งเครือข่ายภายนอก = แดงปลอมได้** — CI ที่ไปดึง API production สดทุกคำขอ ต้องมี timeout + retry + log + readiness ครบทุกปลายทาง
4. **PR เขียว ≠ main เขียว** — ต้องดู post-merge run ด้วย (เจอ flake ที่ขั้นเตรียม preview)
5. **ด่านล็อกความจริงเก่า** (เช่น lastmod) ต้อง **อัปเดตค่าที่คาดหวังให้ตรงของจริง** ไม่ใช่ลบ/ผ่อนด่าน
6. **ไฟล์แช่แข็ง/โทเคน:** แก้ได้เฉพาะ "ปักสีเป็นจุด ๆ" ที่ได้รับอนุมัติ · ห้ามเปลี่ยนค่าโทเคนเพื่อแก้ปัญหาเฉพาะหน้า
7. **หนึ่งคำสั่งต่อคนต่อรอบ** — การส่งคำสั่งเป็นชิ้น ๆ ทำให้คนทำงานสับสน (เกิดจริงกับบอย 11 ต.ค.)
