คุณกำลังรับช่วงต่อการพัฒนาเว็บ Knight Basins ต่อจาก Claude Code ครับ อ่านให้ครบก่อนเริ่มทำงานใดๆ

## โปรเจกต์
- Repo: github.com/Knightfurnich/KnightBasins-Source (branch main)
- Stack: pnpm workspace — artifacts/knight-basins (React/Vite storefront+admin), 
  artifacts/api-server (Express 5), lib/db (Drizzle/Postgres), 
  lib/api-spec+lib/api-zod+lib/api-client-react (Orval-generated — 
  แก้ที่ lib/api-spec/openapi.yaml แล้วรัน `pnpm --filter @workspace/api-spec run codegen` 
  ห้ามแก้ไฟล์ generated ตรงๆ)
- Production: VPS "Knight Design" (srv1964473.hstgr.cloud, 72.62.79.84), 
  Docker Compose + Traefik ที่ /docker/knightbasins/
- Deploy อัตโนมัติ: push ขึ้น main → GitHub Actions build + restart container ให้เอง
  ⚠️ deploy/hostinger/ ไม่ auto-sync ขึ้น VPS — ถ้าแก้ไฟล์ .sh ในนี้ต้อง scp มือเอง (ดู deploy/hostinger/README.md)

## กฎเหล็ก — อ่าน CONTRIBUTING.md ที่ root ของ repo ก่อนแตะ deploy/migration/backup ใดๆ
1. ห้ามรายงานว่า "สำเร็จ/ผ่านแล้ว" โดยไม่มีหลักฐานจริง (curl จากภายนอก, SSH เช็ค timestamp/hash จริง) — 
   เคยเจอ bot ปลอมรายงาน "PASSED 100%" มาแล้วครั้งหนึ่ง
2. ห้าม push ไฟล์ที่กระทบ deploy/backup/migration เข้า main โดยไม่ผ่านการรีวิว
3. Migration file ใหม่ต้อง commit ทันที ห้ามค้าง
4. ไฟล์ .sh ต้องเป็น LF เท่านั้น (Windows autocrlf ทำ CRLF แล้วสคริปต์พังบน Linux)
5. ห้าม commit credential ใดๆ เข้า repo นี้เด็ดขาด (เป็น public repo)

## กฎการทำงานกับผม (เจ้าของโปรเจกต์)
- คุยกับผมเป็นภาษาไทยเสมอ (โค้ด/commit message เป็นอังกฤษได้ปกติ)
- ห้าม deploy ขึ้น production โดยไม่ถามก่อนทุกครั้ง แม้จะทดสอบผ่านหมดแล้วก็ตาม — 
  ต้องถามว่า "push+deploy เลยไหม" ทุกครั้งไม่มีข้อยกเว้น
- ก่อนแก้ไข/ลบอะไรบน production ต้อง list ให้ดูก่อนว่าจะทำอะไร เพราะอะไร
