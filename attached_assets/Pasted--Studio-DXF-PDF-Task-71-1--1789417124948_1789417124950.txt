สรุปใบงานฉบับรวมสุดท้าย — ส่งออกผัง Studio เป็น DXF/PDF (Task #71 ระดับ 1)
(งานข้ามคืนชุดก่อนหน้าปิดครบแล้ว ผัง L/U ทรงจริง · ปัดเศษยอด · ปุ่มกด Telegram · หน้า้นหาใบเสนอราคา — ไม่ต้องทำซ้ำ)

วัตถุประสงค์ที่ผู้ใช้อนุมัติ:
1. ให้ช่างแบบเปิดวัดขนาด (ทีมงานใช้ SketchUp)
2. ให้ลูกค้าดูแบบ → ต้องมี PDF ด้วย เพราะลูกค้าเปิด DXF ไม่ได้
ไม่ใช่ระดับ CNC → รอบนี้ไม่ต้องใส่ความหนาแผ่น · แนวเชื่อมต่อ · รัศมีมุม

ขอบเขตงาน:
1. ปุ่ม "ดาวน์โหลดแบบ (DXF)" และ "ดาวน์โหลดแบบ (PDF)" — มีทั้งหน้า Studio และหน้า saved quote
2. DXF หน่วยมิลลิเมตรแท้ (1 unit = 1 mm) พิกัดตามขนาดจริง — เปิดใน SketchUp Pro ได้ตรง ๆ
3. รองรับผัง I / L / U ตามสัดส่วน A / B / C × ความลึก
4. ใช้ geometry ชุดเดียวกับที่หน้าเว็บใช้คำนวณ/ตรวจความปลอดภัย ห้ามเขียนสูตรซ้ำ
5. แยกเลเยอร์ใน DXF:
   COUNTER_OUTLINE (ขอบเคาน์เตอร์ตามรูปทรงจริง)
   CLEARANCE_50 (เส้นระยะขอบ 50 มม. ตามรูปทรงจริง)
   BASIN_HOLES (กรอบหลุมอ่างตามขนาดจริง)
   BASIN_LABELS (ป้ายรหัสรุ่น SKU)
   DIMENSIONS (เส้นบอกขนาด A/B/C และความลึก)
   NOTE (ข้อความกำกับ)
6. ในเลเยอร์ NOTE ต้องมีข้อความ: "แบบอ้างอิงเพื่อการนำเสนอ ไม่ใช่แบบผลิตหรือแบบ CNC — ต้องตรวจสอบหน้างานก่อนผลิต"
7. รุ่นที่แคตตาล็อกไม่ระบุขนาดหลุม → กรอบเส้นประ + ข้อความ "แคตตาล็อกไม่ระบุขนาดหลุม" ห้ามเดาขนาด
8. ชื่อไฟล์สื่อความหมาย เช่น <เลขที่ใบเสนอราคา>-<ทรง>.dxf / .pdf
9. PDF ต้องหน้าตาเดียวกับผังที่แสดงในใบเสนอราคา
10. automated tests: รูปทรง I/L/U · ขนาด · ตำแหน่งอ่าง · กรณีไม่มีขนาดหลุม · หน่วยเป็นมิลลิเมตร

เกณฑ์ตรวจรับ (แนบหลักฐานจริงทีละข้อ):
1. ดาวน์โหลด DXF ได้จากหน้า Studio และหน้า saved quote (แนบภาพ)
2. เปิดไฟล์ DXF เห็นรูปทรงถูกต้อง I / L / U อย่างละ 1 ไฟล์ (แนบภาพ)
3. พิกัดในไฟล์เป็นมิลลิเมตรจริงตรงกับที่กรอก (แนบภาพ)
4. เลเยอร์ครบ 6 ชื่อตามที่กำหนด + มีข้อความใน NOTE (แนบภาพ)
5. รุ่นที่ไม่ระบุขนาดหลุมขึ้นกรอบเส้นประ + ข้อความถูกต้อง (แนบภาพ)
6. PDF ที่ดาวน์โหลดได้เหมือนผังในใบเสนอราา (แนบภาพ)
7. ผลรันเทสต์ทั้งหมด + build/asset guard ผ่าน (แนบผลรัน)

ห้ามแตะ: Auth/Session · Admin Guard · Persona น้องไนท์ · ข้อมูลอ่างและราคาในฐานข้อมูล · กฎราาเดิม · รุ่นกลมต้องเป็น Ø ห้าม D · ห้ามใส่ token ลงโค้ดหรือ bundle
ห้าม deploy production เอง — push ขึ้น GitHub branch main (source + tests + deploy/ + api-dist/ + web-dist/) พร้อมแจ้ง commit + SHA-256 แล้วเดวิดจะตรวจและขึ้น VPS ให้
