---
name: Hostinger VPS deployment access
description: Constraints for deploying the Knight Basins release to the shared Hostinger server.
---

The VPS is reachable at the Knight Basins hostname, but deployment cannot be assumed from the presence of workspace SSH secrets alone: a valid remote username and an SSH credential accepted by the server are required before any release upload or service restart. The live Knight Basins API currently runs under Docker Compose at `/docker/knightbasins`, with runtime values in its `.env`; the checked-in systemd unit and `/etc/knight-basins/api.env` are not the active production path. The approved password-based SSH path is currently more reliable than the malformed private-key values exposed to the workspace.

**Why:** The configured key and password were present but did not authenticate during a deployment verification attempt, so guessing users or changing production was unsafe. The working access path was the approved `root` account with the server-accepted SSH credential.

**How to apply:** Verify the approved VPS username and refresh the matching SSH credential before retrying the documented Hostinger release procedure. Inspect the active Compose project before editing or restarting production; do not assume the checked-in systemd deployment files describe the live service. The active release copies `artifacts/api-server/dist/` into `/docker/knightbasins/api-dist/` and `artifacts/knight-basins/dist/public/` into `/docker/knightbasins/web-dist/`, then runs `docker compose up -d --force-recreate --no-build api web`. If `rsync` is unavailable, stream each directory as a tar archive over SSH. Apply database schema changes before restart; for the current shared Docker database, a temporary migration container must use `--network container:knightbasins-api` so the `knightdesign-db` Docker hostname resolves. Validate the public storefront, `/api/healthz`, and `/api/catalog` after restart. Persistent admin image uploads require the Compose bind mount `./uploads:/app/uploads`; keep `/api/` Nginx routing as `location ^~ /api/` so the static-asset regex cannot turn `/api/uploads/*.png` into a false 404.
